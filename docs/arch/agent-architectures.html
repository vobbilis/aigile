September 9 documentation refresh. Agent Host owns sessions independently of editor windows; the Copilot SDK owns its agent loop. Local sessions still require VS Code to stay running. Parallel subagents return results to their coordinator; invocations are stateless, not persistent peer conversations. Separately, Agent Host session-management tools support queued chat-to-chat messages, including across sessions (VS Code 1.137). This is not a shared team task board. Nested delegation is opt-in, to depth five. Hooks, memory, telemetry, and sandbox labels describe documented VS Code capabilities, not guaranteed parity across every harness or cloud runtime. Agent Host does not load prompt files; the legacy Local agent still does.

Across all three products · September perspective

Harnesses are growing into agent control planes.

Claude Code

Runtime orchestration: nested and resumable agents, script-driven Workflows, peer messaging, and experimental teams extend the tool loop with coordination and lifecycle control.

GitHub Copilot / VS Code

Session and workflow control: Agent Host manages sessions independently of editor windows; the Copilot SDK runs the agent loop. Parallel delegation, session messaging, and packaged review and PR flows add coordination across surfaces.

Codex

Supervisor and worker control: inspectable, steerable parallel threads, hooks, approvals, and telemetry extend the execution harness. A shared peer board remains an external MCP composition, not a native team service.

Opinionated Agentic Workflows

September 9, 2026: recurring practices are becoming vendor-maintained product experiences.

Interpretation: vendors are packaging review, research, completion checks, and recurring maintenance with named entry points, specialist roles, and lifecycle controls. This standardizes workflows within products, not a common cross-vendor workflow protocol. A reusable skill supplies instructions; an agent-led flow adds built-in roles and checkpoints; a runtime-controlled workflow puts sequencing and intermediate state in code. A scheduler supplies triggers, not proof of deterministic execution. These categories can overlap.

Claude Code · Routines Saved prompt, repositories, environment, and connectors run on schedule, API call, or GitHub event. Trigger starts a fresh cloud session; agent interprets the saved task. Research preview, claude.ai Pro/Max/Team/Enterprise; not Bedrock/API-key authentication. No in-run approval prompts; scope connectors carefully.
Codex · /review Select a base branch or uncommitted changes and receive prioritized findings without modifying the working tree. Dedicated agent-led review contract; current chat or a detached review chat. Fixes require a follow-up request. Documented product flow. Follow-up edits use normal sandbox/approval rules; a clean review is not proof of correctness.

Distinctive implementations, not exclusivity claims: Claude combines script orchestration, peer messaging, and prompt/agent evaluator hooks (agent handlers experimental). Copilot combines a multi-harness VS Code host and session handoffs with a packaged cross-family critic in its CLI. Codex combines inspectable, steerable worker threads with exact-definition-hash trust review for non-managed hooks; its prompt and agent hook handlers are currently parsed but skipped. Skills, hooks, cloud execution, and parallel agents alone no longer distinguish a product.

Implication for Aigile: use built-in flows where their scope and controls match the job. Keep repository-specific acceptance criteria, executable validation, approval boundaries, and audit evidence explicit. A second model or named workflow does not replace those gates.
